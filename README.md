# התקציב שלי

## ניהול תקציב אוטומטי — מסך ״כמה פנוי לי״

מסך `/plan.html` הוא מנהל תקציב **קלנדרי** נפרד מהתזרים הקיים. מסגרת ההקצאה המאושרת: 12,500 ₪ לחודש (7,035.34 ₪ מחויב; 4,322 ₪ לשמור; 1,142.66 ₪ חופשי). קנייה נרשמת פעם אחת במועד הקנייה, ללא קשר ליום חיוב האשראי; מספר הימים שנותרו מחושב מחדש. חריגה מקטינה מיד את ״הסכום הפנוי הבטוח״.

המסך מאפשר רישום הוצאה, שיוך לקטגוריה, העברה תקציבית בין קטגוריות, מעקב אחרי יתרות פיקדונות, שימוש בכסף שכבר נצבר בקרן, תיקון שיוך לקרן וסגירת חודש עם הפקדות מוצעות. הפקדה מוצעת **אינה העברה בנקאית**; יתרת הפיקדון מתעדכנת רק לאחר אישור המשתמש שביצע את ההפקדות בפועל. יתרת פתיחה לקרן דורשת הזנה חד-פעמית של יתרה קיימת ומאומתת. אשראי, משכורת והלוואות ממשיכים להתנהל בנפרד במסך התזרים.

בעת סגירת חודש: יתרות חופשיות וקטגוריות שוטפות נשלחות לרזרבה, ויתרות קטגוריות נצברות נשלחות לפיקדונות התואמים. סגירת חודש מותרת רק אחרי סיום החודש וללא חריגות; גם נובמבר 2026 הוא חודש מלא מה־1 עד ה־30, במסגרת של 12,500 ₪, ונסגר לפי אותם כללים כמו כל חודש. אישור הפקדות נעשה ידנית לאחר בדיקת הכיסוי בבנק. הפעולות נשמרות בענן כחלק מנתוני התקציב הקיימים ומסתנכרנות בין מכשירים.

**מגבלות:** אין חיבור שמאפשר לבצע העברות כספים בבנק או לקלוט באופן מלא תנועות דיירקט/מזומן ללא דיווח. אפשר לסנכרן עסקאות אשראי באמצעות החיבור הקיים, ואין לרשום אותן שוב באופן ידני. אין לראות ביתרה התקציבית אישור לכיסוי בנקאי עד להתאמה עם תשלומים ממתינים.

אתר תקציב אישי בעברית: מחזור משכורת, קבועות, חובות, מזומן, אשראי ובוט טלגרם. היתרות מחושבות לפי מידע שהוזן; אין חיבור לבנק.

## פיתוח ובדיקת השינויים ללא פריסה

```sh
npm ci
npm test
npm run dev
```

פתח `http://localhost:3000`. הכפתור **פתיחת נתוני הדוגמה ללא קוד** פותח תקציב בדיקה בזיכרון בלבד. ההדגמה אינה פונה ל-Netlify או לטלגרם ואינה משתמשת בנתוני אמת. אתחול השרת מאפס אותה. נתיב `/demo` קיים רק בשרת הפיתוח ואינו נארז באתר.

`npm run build` מעתיק ל-`dist` רק HTML, קוד הדפדפן והמודולים הציבוריים. קוד השרת, בדיקות וקובצי הגדרות לא מוגשים כתוכן סטטי. גרסת Node המומלצת היא 24 לפי `.nvmrc`.

## לפני פריסה ראשונה של התיקון

1. הורד גיבוי של `simple-budget/shared-budget` דרך Netlify Blobs. הקוד ממשיך להשתמש באותו מיקום ומבנה נתונים; אין למחוק או לאפס אותו.
2. הגדר ב-Netlify משתנה סביבה **BUDGET_ACCESS_KEY**, זמין ל-Functions בייצור: קוד אקראי וחזק באורך 8 תווים לפחות (מומלץ 16+). צור אותו במנהל סיסמאות ושמור אותו שם; אל תכניס אותו למאגר, ל-PR, לקובץ ציבורי או להודעת צ'אט.
3. השאר את משתני הטלגרם הקיימים. אל תגדיר `BUDGET_LOCAL_DEMO` ב-Netlify.
4. לאחר אישור השינויים, מזג את החבילה ל-`main` בפריסה אחת. אם עדיין מופיע `[skip netlify]` בהודעת המיזוג, הסר אותו בהודעת המיזוג בלבד, או הפעל פריסה ידנית אחת של אותה גרסה.
5. בדוק באתר החי: כניסה, שימור הנתונים הקיימים, הוספת הוצאה, רענון במכשיר נוסף, טלגרם ויציאה. הסר את הוצאות הבדיקה בסיום.

ללא קוד שרת תקין, ה-API חסום (503) ולא חוזר למצב ציבורי. הכניסה משתמשת בעוגייה חתומה, HttpOnly, Secure ו-SameSite=Strict לשבעה ימים. החלפת הקוד מבטלת עוגיות קודמות. הנתונים המקומיים נשארים בדפדפן לצורך שינויים ממתינים; זה אינו תחליף לחשבון מערכת מוגן במכשיר משותף.

## עבודה במנות גדולות וחיסכון בפריסות

- בצע תיקונים ובדיקות מקומית, ושמור בענף עבודה נפרד.
- כל commit ביניים נשמר עם `[skip netlify]`; גם כותרת ה-PR כוללת `[skip netlify]` כדי למנוע Deploy Preview אוטומטי.
- אל תמזג ל-`main` לפני אישור. בסיום מזג את כל החבילה פעם אחת.
- אפשר לבדוק תוכנית ויתרת קרדיטים ב-Netlify תחת Usage & billing. אין בקוד הזה שינוי בתוכנית או חיוב.

תיעוד: https://docs.netlify.com/deploy/manage-deploys/manage-deploys-overview/#skip-a-deploy

## מודל הנתונים והסנכרון

- מחזור התקציב מתחיל ביום המשכורת ומסתיים יום קודם למשכורת הבאה. תאריך היום באתר ובבוט מתייחס לישראל.
- משיכת מזומן מעבירה כסף מהבנק לארנק; היא לא הוצאה.
- תשלום חוב שומר את רכיב הקרן אם הוזן, ומחיקתו מחזירה את הקרן ליתרת החוב. תשלומים היסטוריים שלא שמרו רכיב קרן אינם ניתנים לשחזור אוטומטי; מופיעה אזהרה לפני מחיקתם.
- יתרה קודמת באשראי מתווספת לקניות שנרשמו. חשבון כולל מכסה את הקניות שכבר היו ידועות בעת הזנתו; קניות חדשות אחריו מתווספות. רשומות ידניות ישנות נחשבות ליתרה קודמת בהתאם לתיאור המקורי בטופס. אפשר לתקן חשבון קיים ולבחור **חיוב עתידי — עדכון הסכום בלבד**.
- רישום יעד לעודף הוא תכנון בלבד, ואינו מעביר כסף או משלם חוב.
- קריאות Blobs משתמשות ב-strong consistency. כתיבות מותנות ב-ETag דרך `onlyIfMatch` או `onlyIfNew`. שינוי מקביל גורם לניסיון מיזוג נוסף, ולא לדריסת תמונת מצב.
- הדפדפן שומר תמונת בסיס מוכרת לצד שינויים מקומיים. שינויים בשדות שונים מתמזגים. בשינוי סותר לאותו שדה המשתמש בוחר, ונשמר עותק התאוששות מקומי. מכשיר ישן עם שינויים ממתינים דורש בחירה לפני החלפת ערכים קיימים בענן.
- גרסאות לקוח ישנות ללא `If-Match` נחסמות לשמירה (428). יש לרענן אותן אחרי הפריסה.
- שדות קישור הטלגרם, ההודעה הממתינה וזיהוי עדכונים מעובדים נשארים בשרת ואינם ניתנים לשינוי דרך דפדפן.
- בוט הטלגרם מבצע כתיבות מותנות ומנסה מחדש בהתנגשות; מזהה הוצאה מבוסס על מזהה עדכון כדי למנוע רישום כפול.
- פריסות Preview משתמשות במאגר נפרד ואין בהן אפשרות לשנות את webhook הייצור.

## טלגרם

משתני השרת: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_PAIRING_CODE`.
לאחר הגדרתם ופריסה, היכנס לאתר, בחר **טלגרם**, והפעל באמצעות קוד החיבור. שלח לבוט `/pair` ואת הקוד. בוט שכבר מקושר אינו צריך קישור מחדש אחרי התיקון.

## מה נבדק ומה עדיין מחייב בדיקה בייצור

בדיקות Node כוללות חובות, יתרות אשראי, כיסוי חשבון כולל, מיזוג שינויים מקבילים, סנכרון מחיקות, אימות גישה, חסימת מקור זר, כתיבות ETag מתחרות, אימות קלט ומניעת כפל הודעות טלגרם. בדיקת הדפדפן המקומית כוללת טעינה, רישום הוצאה ושימורה לאחר רענון.

השרת המקומי מחקה את חוזה ה-ETag של Blobs, אך אינו מחליף בדיקת Functions ו-Blobs אמיתית אחרי הפריסה המאושרת. יש מגבלת 256KB לעדכון ו-5,000 רשומות לרשימה; שגיאות שמירה מוצגות והנתונים נשארים מקומית. אין כאן בדיקת חדירות או הבטחה להעדר כל תקלה.
